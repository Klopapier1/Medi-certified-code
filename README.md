# Medi-certified-code

An AI orchestration framework that produces medical software code alongside
the traceable evidence package (requirements, design, tests, risk analysis,
traceability) needed to pursue certification under IEC 62304. See
`docs/mvp-scope.md` for the full scope and rationale.

**The framework and any product it generates are deliberately separate:**

- **`orchestrator/`** — the pipeline engine. Product-agnostic: it knows the
  8-stage process and the standard artifact layout, nothing about any
  specific software item's domain.
- **`products/<name>/`** — one software item's output from a pipeline run
  (requirements, design, code, tests, evidence). Each is self-contained and
  disposable; the framework doesn't depend on any of them existing.

## Status

- `orchestrator/` — automated pipeline exists and its non-LLM stages
  (static analysis, test execution, evidence compilation) are tested for
  real against the BMI pilot as fixture data (`orchestrator/tests/`). The
  LLM-driven stages (requirements/design/code/test/risk generation) need
  `ANTHROPIC_API_KEY` to run and haven't been exercised end-to-end yet.
- `products/bmi/` — one IEC 62304 Class A item (`bmi` module) taken
  end-to-end through the 8-stage process, manually orchestrated in a single
  session *before* `orchestrator/` existed, as proof of the artifact model
  (see `products/bmi/evidence/run-provenance.json`, `mode: "manual-orchestration"`).
  It has not been regenerated by the automated pipeline.

## Layout

```
orchestrator/           the pipeline engine (product-agnostic)
  config.py                ProductSpec — the only place a run's parameters live
  client.py                thin Claude API wrapper
  roles.py                 prompt templates for each generative stage
  tools.py                 real pytest/ruff/mypy subprocess wrappers
  evidence.py               traceability matrix + provenance, regex-based, not LLM-asserted
  pipeline.py               the 8-stage Pipeline class
  cli.py                    CLI entrypoint
  tests/                    framework's own tests (no API key needed)

products/<name>/         one software item's pipeline output
  requirements/SRS.md       stable REQ-* IDs
  design/SDD.md             design, traced to REQ-*
  src/<name>.py             implementation, traced to REQ-*/design IDs
  tests/test_<name>.py      tests mapped to REQ-*, real pytest execution
  evidence/                 test-report.md, static-analysis-report.md, sbom.json,
                             risk-table.md, traceability-matrix.md, run-provenance.json,
                             review-signoff.md (the mandatory human gate)

docs/mvp-scope.md        MVP scope and open questions
requirements-dev.txt     shared dev tooling versions (pytest, ruff, mypy) used to
                         verify any product's generated code
```

## Running the pipeline

```
pip install -r orchestrator/requirements.txt   # anthropic SDK
export ANTHROPIC_API_KEY=...
python3 -m orchestrator.cli \
  --name widget \
  --requirement "plain-language description of what it should do" \
  --output-dir products/widget
```

Fails fast (before writing anything) if `ANTHROPIC_API_KEY` is unset.
Nothing in `products/<name>/` is final until a human fills in
`evidence/review-signoff.md` — the pipeline writes it as a blank template,
never as pre-approved.

## Running the checks

Framework tests (no API key needed):
```
python3 -m pytest orchestrator/tests/ -v
```

A given product's checks (e.g. the BMI pilot):
```
python3 -m pytest products/bmi/tests/ -v --cov=src.bmi --cov-report=term-missing
cd products/bmi && ruff check src/ && mypy --strict src/
```
